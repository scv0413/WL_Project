# Core-first Snatch Analysis Development Design

작성일: 2026-08-19
제품 기준: `docs/plans/2026-08-05-001-feat-snatch-coach-analysis-v1-plan.md`

## 목적

처음부터 54개 영상을 모두 처리하는 완성형 시스템을 만들지 않는다. 먼저 대표 영상 1개에서 Pose Estimation과 원판 Object Detection이 함께 동작하는 최소 end-to-end core를 만들고, 각 단계의 측정 결과와 실패 원인을 확인하며 적용 범위를 넓힌다.

core는 자세의 정답이나 종합 점수를 출력하지 않는다. 관절 좌표·각도, 원판 중심·바벨 궤적, 수동으로 지정한 동작 구간과 신뢰도를 코치가 확인할 수 있는 형태로 저장하고 보여주는 것이 첫 목표다.

## 현재까지 확보한 기반

### 완료된 작업

- 제품 범위, 해석 한계와 다섯 동작 구간을 요구사항 문서와 `AGENTS.md`에 정리했다.
- Python 3.12, `uv`, `.venv`, PyTorch MPS 환경을 구성했다.
- 54개 MP4를 `data/raw/videos/`에서 관리한다.
- `metadata.py`에서 파일명 파싱, OpenCV 영상 속성 추출과 Manifest 생성을 구현했다.
- `data/metadata/videos.csv`에 54개 영상, 24명, A/B/C, `f/h`, FPS, 프레임 수와 해상도를 기록했다.
- `01_data_diagnosis.ipynb`에서 Manifest를 안전하게 생성하거나 불러오는 흐름을 구현했다.
- Manifest 재생성 기본값을 끄고 수동 메타데이터가 덮어써지지 않는 실행 테스트를 만들었다.

### 확인된 성공

- 54개 영상 모두 OpenCV로 읽을 수 있다.
- Manifest의 54개 `video_id`가 중복 없이 생성된다.
- 기존 Manifest를 불러오는 노트북 실행 전후 CSV 해시가 동일하다.
- 현재 메타데이터 및 노트북 테스트 4개가 통과한다.
- M2의 MPS 장치를 PyTorch에서 사용할 수 있다.

### 확인된 실패와 학습

- `unittest` 파일 경로를 모듈 경로처럼 실행하면 `tests`가 패키지가 아니어서 실패했다. 테스트는 discovery 방식으로 실행한다.
- 샌드박스 안에서 Jupyter 커널을 실행하면 로컬 포트 권한 오류가 발생했다. 실행 검증은 승인된 로컬 커널 권한으로 수행한다.
- `.venv/bin/python -m jupyter nbconvert`는 PATH의 Anaconda 실행기를 선택해 프로젝트 패키지를 찾지 못했다. `.venv/bin/python -m nbconvert`로 가상환경 모듈을 직접 실행한다.
- Pydantic은 현재 한 개의 Manifest 경계에는 이득보다 의존성·설정 비용이 크다고 판단해 보류했다. FastAPI 또는 여러 공통 데이터 계약이 생기면 다시 검토한다.

## 최소 core 정의

최소 core는 대표 스내치 영상 1개를 입력받아 다음 결과를 한 번에 만든다.

1. 주동작 선수의 프레임별 COCO 관절 좌표와 신뢰도
2. 몸통·무릎·엉덩이 등 선택한 관절 각도
3. 커스텀 원판 탐지 결과와 프레임별 bbox 중심
4. 원판 중심을 연결한 바벨 궤적
5. 수동 이벤트 프레임으로 구분한 다섯 동작 구간
6. 관절·원판 overlay 영상, 각도 표·그래프와 바벨 궤적 그래프
7. 탐지 실패, 낮은 신뢰도와 계산 불가 항목의 `N/A` 사유

core에서는 구간을 자동 판정하지 않는다. 사용자가 먼저 표시한 이벤트 프레임을 사용해 Pose·원판·각도·궤적 연결이 맞는지 검증한다. 자동 구간 탐지는 core가 안정된 뒤 추가한다.

## 개발 흐름

### 1. 데이터 진단 완료

- 54개 영상의 분포와 대표 프레임을 확인한다.
- `has_plate`, `camera_motion`, 가림, 주변 인물과 촬영 각도 상태를 기록한다.
- 대표 core 영상은 원판이 있고, 측면에 가깝고, 전체 동작이 포함된 `f` 영상에서 고른다.

### 2. 블라인드 기준 만들기

- 모델 결과를 보기 전에 대표 영상의 이륙, 무릎 통과, 최대 신전, 캐치와 Recovery 프레임을 기록한다.
- 바벨 전후 이탈을 `있음`, `없음`, `판단 어려움`으로 기록한다.
- 이 값은 모델을 학습시키기 위한 정답보다 baseline 결과를 비교할 기준으로 사용한다.

### 3. Pose core

- 작은 사전학습 YOLO Pose 모델로 대표 영상 전체 프레임을 추론한다.
- 주변 인물이 있을 때 주동작 선수 선택 기준을 확인한다.
- 원본 좌표·신뢰도를 저장한 뒤 모델을 재실행하지 않고 각도와 시각화를 반복한다.
- 가림과 낮은 신뢰도에서 값을 임의 보간하지 않고 실패 사유를 남긴다.

### 4. 원판 Detection core

- 대표 영상 중심의 작은 원판 라벨 세트를 만든다.
- 작은 YOLO Detection 모델을 먼저 학습해 검출 가능성을 확인한다.
- bbox 중심을 프레임별로 저장하고 끊김·오탐·주변 원판 혼동을 실패 사례로 분류한다.
- 바벨 전체 bbox를 별도로 학습하는 구조는 원판 중심만으로 부족하다는 증거가 생길 때 검토한다.

### 5. 단일 영상 결합

- 동일한 `video_id`와 `frame_index`를 기준으로 Pose와 원판 결과를 결합한다.
- 수동 이벤트 프레임으로 다섯 구간을 나눈다.
- overlay 영상, 대표 프레임, 각도와 궤적을 한 노트북에서 재생성한다.
- 이 지점이 최소 core의 완료 기준이다.

### 6. 점진적 고도화

core 검증 후 한 번에 한 축만 넓힌다.

1. A/B/C에서 대표 영상 1개씩 총 3개로 확대
2. 동일 인물의 반복을 포함한 작은 개발 세트로 확대
3. 주동작 선수·원판 선택과 추적 안정화
4. 자동 구간 후보 생성과 수동 라벨 비교
5. 블라인드 라벨로 바벨 전후 이탈 임시 기준 보정
6. `h` 영상, 원판 없는 영상과 낮은 신뢰도의 부분 결과 처리
7. 54개 전체 성공·부분 성공·실패 진단

ONNX, FastAPI, Docker와 AWS는 54개 전체 진단에서 측정 신뢰성과 출력 계약이 안정된 후 별도 단계로 다룬다.

## 로컬 작업일지 플러그인

Git에 포함되지 않는 프로젝트 전용 로컬 플러그인을 두고 다음 기록을 유지한다.

- `decisions.md`: 검토한 선택지, 선택 결과와 근거
- `attempts.md`: 실행한 접근, 성공·실패, 오류와 해결 방법
- `checkpoints.md`: 단계별 데이터 수치, 테스트와 모델 평가 결과
- `commits.md`: commit 해시, 작업 범위와 관련 기록 위치

현재까지의 결정과 실패도 최초 생성 시 역기록한다. 영상 경로, 사람 식별 정보와 민감한 결과는 기록하지 않는다.

플러그인은 저장소 밖의 개인 플러그인 디렉터리에 두어 Git에 올라가지 않게 한다. 프로젝트의 `AGENTS.md`에는 작업 전후로 이 일지를 갱신해야 한다는 규칙만 남긴다.

## Commit 규칙

- 검증 가능한 작업 단위 하나를 commit 하나로 만든다.
- 서로 다른 책임의 변경을 한 commit에 섞지 않는다.
- 테스트가 실패한 상태는 commit하지 않고 `attempts.md`에 기록한다.
- 각 commit 전 관련 테스트와 최소 실행 검증을 수행한다.
- 문서·데이터 진단·Pose·원판 Detection·결합·피드백을 각각 독립 commit 경계로 둔다.
- 자동 생성 데이터, 원본 영상, 모델 가중치와 로컬 작업일지는 commit하지 않는다.

현재 미커밋 상태인 데이터 진단 노트북과 실행 테스트는 하나의 작업 단위로 먼저 commit한다. 이후 로컬 작업일지 플러그인 구성, 데이터 진단 확장과 각 core 단계는 각각 별도 commit으로 진행한다.

## 검증 원칙

- 각 단계는 대표 입력과 기대 출력을 먼저 정한 뒤 구현한다.
- 노트북은 처음부터 끝까지 실행하거나 실행하지 못한 정확한 이유를 남긴다.
- 모델 평균값만 보고 통과시키지 않고 최악 사례와 `N/A` 사례를 함께 본다.
- core 완료는 모델 파일 존재가 아니라 한 영상에서 저장 결과와 시각화가 재현되는 것으로 판단한다.
- 고도화는 이전 checkpoint보다 무엇이 개선되었고 무엇이 악화되었는지 비교할 수 있을 때만 채택한다.

## 범위 밖

- 학습 기반 종합 자세 점수
- 엘리트 경기력 등급과 선수 순위
- 중량·근력·경력 정보가 없는 상태에서 오류 원인 단정
- core 검증 전의 자동 배포와 경량화
- 처음부터 모든 영상과 예외를 동시에 지원하는 대규모 파이프라인
